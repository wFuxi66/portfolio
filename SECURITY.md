# Security Policy

This is a personal portfolio site. It serves static content and does not process user accounts, forms, payments, or any server-side logic. Despite that, responsible disclosure is still appreciated.

## Scope

In scope:

- The deployed site (GitHub Pages)
- Source in this repository
- Third-party dependencies pinned in `package.json`

Out of scope:

- External services I only link to (LinkedIn, GitHub, mail clients, etc.)
- Social engineering against the author

## Reporting a vulnerability

Email **zhengjimmy66@gmail.com** with:

- A short description of the issue
- Reproduction steps or a proof of concept
- The affected URL, commit hash, or file

Please do not file public GitHub issues for security problems. I aim to acknowledge reports within 5 business days.

## What counts

Reports I care about:

- XSS or markup injection through any rendered content
- Credential, token, or secret accidentally committed to this repo
- Misconfigured `.github/workflows/deploy.yml` allowing untrusted code to publish
- Supply-chain concerns in pinned dependencies (please cite the advisory)

Reports I will usually decline:

- Missing security headers on static content that poses no real risk
- Best-practice suggestions without a concrete threat model
- Reports generated by unreviewed automated scanners

## Dependencies

Dependency versions are pinned in `package.json` and `package-lock.json`. GitHub's default Dependabot alerts apply to this repository.

## Disclosure

Once a reported issue is fixed, I am happy to credit the reporter in the commit message or release notes if they want credit.
